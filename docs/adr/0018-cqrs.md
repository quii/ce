# 0018: CQRS

## Decision

Writes and reads take entirely separate paths - writes append events, reads are served from read-optimised projections built from those events.

## Rationale

This isn't CQRS for its own sake - it falls directly out of the auditability requirement in `brief.md`. See `docs/adr/0019-event-sourcing-transactional-outbox.md` for the mechanics this produces.

## Consequences

Reads are eventually consistent with the event log by design (see `docs/write-path.md`), which is a real, stated trade-off, not an accident.

## Enforcement

None directly - this is a decision recorded for context. The individual mechanics it produces (domain purity, the write path) are covered and enforced by their own ADRs.
